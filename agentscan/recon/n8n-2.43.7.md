# Recon report — n8n 2.43.7 (local instance)

Date: 2026-10-17 · Mode: automated/local · Accounts: owner + 2 member accounts · Synthetic data only
Target: `docker.n8n.io/n8nio/n8n:latest` (2.43.7) on 127.0.0.1:5678

## Context noticed immediately
- **100+ security advisories**, including a **fresh batch published 2026-10-14** (3 days before this
  recon): OData filter injection, credential theft via error workflows, Read/Write Files event-loop
  DoS, chat hub tool registration, token storage in failed executions. The project is actively
  patching; main branch is likely post-fix. Treat as hardened.

## Low/informational notes
- Member directory exposes emails to any authenticated member (n8n sharing model; likely intended).
- `CSP` is report-only, no frame-ancestors enforcement observed (clickjacking surface, low).
- Session cookie lacks `Secure` when `N8N_SECURE_COOKIE=false` (deployment-dependent).

## Methodology lessons
- **Boot timing**: migrations delay route mounting; healthz ≠ routes ready. Wait for `/rest/settings`
  200 before running the matrix.
- **n8n 2.x API drift**: invitations are array-only; accept uses a JWT token; activation requires
  `versionId`. Test-harness must track the current REST contract.
- Webhook registration depends on node `typeVersion`; use current webhook node shapes when testing
  webhook auth/paths.

## Verdict
No exploitable finding on this pass. n8n's authz/permission model held under multi-user IDOR tests;
public REST surface is minimal; the project just shipped a large security release. Same conclusion as
Open WebUI: **hardened targets, wrong place for a first CVE — but good for calibration and for
0din-style app-chain tests.**

Next targets (less advisory density, bigger unauthenticated/tool surfaces): Flowise, Langflow, Dify,
LibreChat. Keep the harness matrix: boot → owner setup → second user → IDOR (workflows/credentials/
files/KB) → public surfaces (webhooks, share links, file endpoints) → SSRF sinks → injection sinks.
